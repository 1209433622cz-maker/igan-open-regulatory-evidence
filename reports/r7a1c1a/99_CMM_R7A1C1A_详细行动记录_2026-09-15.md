## 3. IL12RB2 运行时修复与完整交集

原脚本通过 `itertuples()` 迭代 TenK 行，却用 `qr["p.value"]` 读取含点号列，实际运行立即失败。该问题不会被 `py_compile` 发现。

完成修复：

- `p.value` 在读入后重命名为 `p_value`；
- 验证 TenK required columns；
- 验证精确 overlap 数、duplicate、finite beta/SE/AF、正 SE、AF 范围；
- posterior 未达冻结门时 fail closed。

实跑结果：完整 PBC GWAS 经 liftover 和 allele orientation 后，与 TenK NK IL12RB2 有 396 个精确共同变异。

```text
p12=1e-6: PP.H4=0.9759733835; H4/(H3+H4)=0.9759733835
p12=1e-5: PP.H4=0.9975442350; H4/(H3+H4)=0.9975442350
p12=1e-4: PP.H4=0.9997538795
```

R7A1C0 的 292-rsID bridge 限制被解除。TenK source-CS variants 仍没有进入疾病/QTL精确交集，因此 source-CS 一致性继续依赖已经审计过的 EUR503 外部 LD；没有把它误写成 TenK native LD。

## 4. FCRL3 TenK 字节级接入

TenK 完整 ±100 kb QTL ZIP 为 16,559,137,990 bytes。为避免下载整个 ZIP，本轮根据 ZIP central directory 只获取预冻结 `B_intermediate_common_all_cis_raw_pvalues.tsv` 成员。

成员接入参数：

```text
local header offset = 605,710,861
compressed bytes = 591,715,279
uncompressed bytes = 2,392,868,507
CRC32 = 3c73842b
```

71 个范围分块中 70 个常规完成；一个 8 MiB 范围反复发生连接中断。本轮没有跳过该分块或接受不完整数据，而是将该范围拆成 32 个 256 KiB 子范围并行重建。重建分块 SHA-256：

`af76258f697af55fe1f9054a32c1c7d44e68d47cc29deb42433df309fc1e4e55`

随后重新拼接完整压缩成员并执行 raw-DEFLATE EOF、uncompressed byte count、CRC32、row width 和 exact gene filter。全部 PASS：

```text
source lines including header = 16,543,537
FCRL3 exact rows = 843
extract bytes = 169,820
extract SHA-256 = 2858979a854e5f59e6bd60b018c12ec0661e79b4effaa044118c190e08b3f4e1
```

因此局部分块修复由完整成员 CRC 作最终真实性裁决，不依赖“文件大小看起来正确”。

## 5. FCRL3 正式 ABF smoke

PBC GRCh37 GWAS liftover 到 GRCh38 后，以 exact position、REF/ALT allele set 和 effect orientation 与 TenK QTL 合并，得到 343 个变异，TenK N=1,918。

```text
p12=1e-6: PP.H3=0.0782743; PP.H4=0.9215758; ratio=0.9217140
p12=1e-5: PP.H3=0.0084219; PP.H4=0.9915620; ratio=0.9915780
p12=1e-4: PP.H4=0.9991497
```

Top conditional shared weights：

```text
rs7528684  0.383992
rs945635   0.249370
rs3761959  0.192827
rs2210913  0.173811
```

这四个变异全部属于 TenK source CS1；预先冻结的 `rs3761959 / 1:157699488:C:T` 同时存在于精确 overlap 与 source CS1。FCRL3 从 `SUPPORTIVE_EXACT_SOURCE_CS_IDENTITY__FORMAL_COLOC_NOT_RUN` 升级为：

`PASS_ROBUST_SINGLE_CAUSAL_ABF_SMOKE_WITH_SOURCE_CS1_IDENTITY`。

TenK source SuSiE 中 FCRL3 共有 45 rows、多个 credible sets；故 ABF 不能被称为最终多信号共定位或唯一因果变异证明。

## 6. HRA 官方字节与先验生物学核验

HRA008003 官方目录和 `md5sum.txt` 确认五个 PBC liver BAM：HRR1849459–HRR1849463。总字节 152,488,497,199，官方 MD5 与 v2 manifest 5/5 匹配，HTTP range 可用。

原始 Nature Communications 研究的补充表显示 FCRL3 是 human liver naive B 和 memory B marker；人肝 marker 表未检出 IL12RB2。该信息提高 FCRL3 liver gate 的先验可行性，但不代替真实 3/5 donor 结果。

2026 BMC Gastroenterology 已用同一 HRA 数据报告 FCRL3 主要位于 B cells 并做 PBC/FCRL3 multi-omics。因此创新性上限被重申：不能声称首次发现 FCRL3 或首次肝 B-cell localization。

## 7. v1 HRA runner 的敌意审计

下载 HRR1849459 首 64 MiB 作结构探针。BAM header 显示 Cell Ranger 3.1、STAR、GRCh38、coordinate sorted。局部结果：

```text
records = 926,729
CB-tagged records = 912,424
unique CB = 45,117
xf bit-8 records = 54,230
unique CB among xf bit-8 records = 14,315
```

原研究每个样本约 5,194 cells、target 6,000 cells；局部 `CB` 已远超真实 cells。R7A1C0 v1 把全部 `CB` barcodes 当细胞，并以 read sets 近似 UMI，可能把 ambient/background target reads 判为供者阳性。

因此正式冻结：

`R7A1C0_HRA_V1_RUNNER = INVALID_FOR_FINAL_ADJUDICATION`。

## 8. v2 HRA runner 的加固

先写出的 v2 曾计划生成未压缩 molecule BAM 并扫描两遍。最终复核发现这会产生不可控工作空间，并使原定 15 GiB margin 不可靠，于是再次改为单遍直接扫描：

- 仅 `xf bit 8` molecule representative；
- 在一次读取中重建每 barcode total UMI 和小型 target panel；
- order-of-magnitude called-cell threshold；
- called cells 2500–7500、median total UMI ≥500；
- B/NK 谱系竞争 gate；
- 每谱系至少 10 called cells；
- promotion eligibility 为 target ≥3 UMIs 且 ≥2 positive lineage cells；
- 同一 target 在 ≥3/5 donors 通过才升级项目。

部署环境：

```text
WSL = Ubuntu-22.04
Python = 3.10.12
pysam = 0.23.3
aria2 = 1.37.0
```

Windows Python 3.13 无可用 pysam wheel，源码构建失败；已将官方 cp310 manylinux wheel保存到本地软件目录并离线安装到 WSL。五供者 runner、双哈希、manifest 和 adjudicator 已闭环。
