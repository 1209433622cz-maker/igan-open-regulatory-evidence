## 4. R7A1C1B0 原 v3 的运行时缺陷

### 4.1 最终 adjudicator 路径损坏

原脚本末尾为：

```powershell
$adjudicateWsl = Convert-ToWslPath (Join-Path $Code '03_adjudicate...py'),
  (Join-Path $Code '07_validate...py'),
  (Join-Path $Code '08_check...py')
```

`Convert-ToWslPath` 只接受一个字符串，却收到三个路径。PowerShell parser 不会识别为语法错误；故只有在五个 donor 全完成后才会暴露，导致最终裁决失败。

v3.1 修复为单一 `03_adjudicate_HRA008003_liver_gate_v2.py` 路径。

### 4.2 固定 500k coordinate prefix 会假失败

原 schema audit 固定只看前 500,000 records，并要求至少 1,000 个 `xf bit 8`。用真实 HRR1849459 前 64 MiB 运行：

```text
records inspected = 500,000
xf bit 8 = 15
status = FAIL
```

这不是 BAM schema 错误，而是 coordinate sorting 使最前方 genomic slice 很少出现 UMI-counted molecule records。自适应继续读取后：

```text
records inspected = 649,995
xf bit 8 = 1,000
CB among xf8 = 1.0
GN among xf8 = 1.0
UB among xf8 = 1.0
unambiguous GN among xf8 = 1.0
status = PASS
```

v3.1 冻结为：至少 500k；达到 1,000 个 xf8 后停止；最大 5M，仍不足则 fail closed。

### 4.3 summary-only resume 证据不足

原 v3 遇到合法 schema summary 即跳过；若 receipt 不存在，会在内存构造 `RECORDED_IN_PRIOR_VALIDATED_RUN`，但不能证明该 summary 之前确实通过 provider MD5。

v3.1 只有以下全部一致才复用：summary run/schema/QC/bytes/SHA；且恰好一个历史 receipt 的 status/bytes/official MD5/observed MD5/SHA 全匹配。孤立 summary 直接停止。

### 4.4 PMC 附件 URL 返回 HTML

原轻量脚本的 PMC URL 返回 HTTP 200，但 content type 是 `text/html`，会以 `.xlsx` 文件名保存网页。v2 改用 Springer 官方二进制端点，并增加 exact bytes、SHA-256 和 `PK\x03\x04` XLSX signature 门。
